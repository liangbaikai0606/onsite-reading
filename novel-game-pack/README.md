# 小说游戏工业化资源包

调研日期：2026-11-19  
用途：为 `novel-to-game` 类技能补充开源运行时、AI 叙事工具、内容生产方法和质量门禁。

## 结论先行

不要试图用一个 GitHub 仓库解决全部问题。建议把一个小说游戏项目拆成四层：

1. **改编层**：理解原文、建立人物/地点/事件索引、识别可交互冲突。
2. **叙事层**：用 Ink、Yarn Spinner 或自定义 JSON 管理分支、变量和结局。
3. **游戏层**：用 Web、Ren'Py、Godot 或 Unity 提供画面、输入、存档和音频。
4. **AI 层**：只负责受限的对话、改述、NPC 反应和内容辅助，不掌握唯一真相。

### 最适合当前需求的快速路线

如果目标是 15 分钟内做出可玩的网页原型：

- **0—1 天原型**：`Shanyin-ai/Story-to-game` 的单文件 HTML + JSON。
- **3—7 天可维护版本**：React/Vite + `inkjs` + TypeScript 状态层 + 本地存档。
- **后续世界探索版**：Phaser + Ink，或 Godot + Dialogic。
- **需要 AI 主持人**：参考 `Sagesheep/NarrativeEngine-P` 的记忆、世界资料和回合管理。
- **只做视觉小说**：Ren'Py；Web 优先时可看 Monogatari；Unity 项目可用 Fungus 或 Yarn Spinner。

## 推荐组合

### 路线 A：最快跑通

```text
小说资料
→ Story-to-game 的九步改编流程
→ 分支 JSON
→ 单文件 HTML 启动器
→ validate.py 校验
```

优点：中文资料完整、网页即开、选择/变量/结局/成就要素齐全。  
限制：适合原型，不宜直接当作大型项目架构；渲染、资产、国际化和持久化都较弱。

### 路线 B：Web 正式版

```text
世界圣经 / 人物卡 / 事件卡
→ Ink 剧本
→ inkjs 运行时
→ React 或 Phaser UI
→ AJV JSON Schema + 自动路径模拟
→ Playwright 端到端测试
```

优点：叙事语法成熟，分支测试方便，Web 部署简单。  
适合：文字冒险、插画视觉小说、轻探索、对话驱动游戏。

### 路线 C：完整游戏引擎

- **2D 探索 + 对话**：Godot + Dialogic。
- **Unity 视觉小说 + 模拟**：Anansi + Ink。
- **Unity 插画互动小说**：Fungus。
- **纯视觉小说**：Ren'Py。
- **Web 视觉小说**：Monogatari。

### 路线 D：AI 主持人

参考 `NarrativeEngine-P` 的以下设计：

- 世界资料分块和检索。
- NPC 长期记忆。
- 回合状态、角色关系和场景回滚。
- 规则集与叙事风格分离。
- 支持 OpenAI 兼容接口或本地 Ollama。

但不要让 LLM 直接拥有主线事实。主线事实应存在于结构化数据库或剧本文件中，LLM 只读取经过检索的事实并生成表达。

## 资源包内容

- `resource_catalog.md`：人工阅读版资源清单、许可证与推荐用途。
- `resource_catalog.json`：可被 AI 或脚本读取的机器版清单。
- `industrial_pipeline.md`：从原著到可发布游戏的工业化流程与质量门禁。
- `skill_upgrade_patch.md`：对现有 `novel-to-game` 技能的具体增补方案。
- `vertical_slice_15min.md`：面向哈利·波特第一册题材的 15 分钟垂直切片设计。

## 建议的最终技能能力

现有技能若只负责“小说转 JSON”，建议升级为四种模式：

1. `quick`：直接生成最短可玩版本。
2. `director`：概念方向和内容取舍处暂停，让用户拍板。
3. `industrial`：完整生产管线、资产清单、测试和版本管理。
4. `live-gm`：AI 主持人模式，有记忆、状态和事实约束。

## 版权与发布

- 哈利·波特等作品属于受版权保护的知识产权。个人学习、非商业原型和同人实验与商业发行不是同一种法律风险。
- 商业产品应取得改编权，或改用完全原创的世界观、人物和专有名词。
- 开源仓库的代码许可证不等于小说版权许可。
- 美术、字体、音乐和音效必须逐项记录来源、许可证和使用范围。
- 若公开分享原型，应避免逐字复制原作大段文本，优先使用摘要、原创场景和原创对白。

## 最重要的设计判断

小说改游戏的核心不是“把段落变成按钮”，而是找到原著中**无法同时满足的价值冲突**：

- 守规矩还是保护朋友。
- 追求真相还是维护安全。
- 获得名声还是保留隐私。
- 相信权威还是相信亲眼所见。

选择必须让玩家失去某样东西，否则只是换了外观的进度条。
