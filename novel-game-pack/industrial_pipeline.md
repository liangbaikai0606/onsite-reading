# 小说游戏工业化流程

## 总原则

小说改编游戏不是把文字换成按钮，而是把“叙述事实”转成“玩家必须承担后果的行动空间”。

工业化需要四份彼此独立的真相：

1. `WORLD_FACTS`：世界规则和不可随意更改的事实。
2. `GAME_STATE`：玩家当前知道什么、拥有什么、改变了什么。
3. `NARRATIVE`：当前场景、选项、分支和结局。
4. `PRESENTATION`：画面、声音、字体、镜头和演出。

AI 可以帮助生产，但不能把这四层混成一段自由文本。

## 阶段 0：权利与范围

交付物：

- 改编权状态说明。
- 商用/非商用边界。
- 允许使用的原作事实、名词、角色和视觉元素清单。
- 禁用内容和二次创作边界。

门禁：

- 没有明确权利，不进入商业发布阶段。
- 不把“代码开源”误认为“IP 可用”。

## 阶段 1：原作摄入

交付物：

- 章节摘要与因果链。
- 人物卡、地点卡、物品卡、组织卡。
- 时间线和视角限制。
- 风格锚点：叙述温度、对白节奏、禁用表达、视角转换。

推荐工具：

- BookNLP：人物、别名、引文和共现抽取。
- 人工事实表：最终事实必须可追溯。
- 结构化 Markdown 或 JSON：一段一 ID。

门禁：

- 每个主要人物有动机、恐惧、知识和不知道的事。
- 每个事件有起因、行动、直接后果和长期后果。
- 不存在只靠段落摘抄才能解释的规则。

## 阶段 2：游戏命题

回答四个问题：

1. 玩家在扮演谁，拥有什么身份压力？
2. 玩家反复做什么动作？调查、说服、潜行、授课、战斗还是经营？
3. 玩家最常面对的价值冲突是什么？
4. 为什么这个故事必须做成游戏，而不是有声书或视觉小说？

交付物：

- 一句话游戏命题。
- 3 个核心动词。
- 2 个不可同时满足的目标。
- 1 个 15 分钟垂直切片。

门禁：

- 删掉专有名词后，核心玩法仍然成立。
- 保留专有名词后，核心玩法明显属于这个世界。

## 阶段 3：选择经济学

每个重要选择至少改变以下两项：

- 时间。
- 资源。
- 关系。
- 知识。
- 信誉。
- 安全。
- 物件归属。
- 未来可用路径。

避免：

- 所有选择只加同一种好感。
- 选项只是礼貌/粗鲁/沉默三种语气。
- 明显正确选项和明显错误选项。
- 只改变 UI 文案，不改变人物和世界。

推荐结构：

- 60% 态度选择：改变关系与信息。
- 30% 路径选择：改变经历和代价。
- 10% 命运选择：导向真正的不同结局。

## 阶段 4：叙事图与 storylet

两种结构可组合：

### 固定主线图

适合主线清晰的小说：

```text
场景节拍 → 分支 → 汇合点 → 后果状态 → 下一章
```

每个汇合点携带不同状态，让同一个场景对不同玩家呈现不同选项。

### Storylet 池

适合开放世界和角色模拟：

```text
storylet:
  conditions
  weight
  cooldown
  effects
  content
```

当条件满足时，由系统选择可用事件，而不是固定节点一路点击。

推荐：

- 主线用固定图，保证主题和结局。
- 日常与 NPC 用 storylet，保证可重玩性。
- 命运级分支必须人工设计，不能完全交给随机系统。

## 阶段 5：状态模型

最少分成六类：

```text
PLAYER_STATS
RELATIONSHIPS
KNOWLEDGE_FLAGS
WORLD_FLAGS
INVENTORY
PROMISES_AND_DEBTS
```

设计规则：

- flag 表示事实，不表示情绪。
- 关系值是 NPC 态度，不是道德评价。
- 知识 flag 表示“玩家知道”，不是“事实为真”。
- 允许角色持有错误认知。
- 每个状态变量都应有可见反馈或剧情用途。

## 阶段 6：内容生产

建议按“内容单元”写：

```text
UNIT_ID
SCENE
PURPOSE
ENTER_CONDITIONS
VISIBLE_TEXT
DIALOGUE
CHOICES
CHANGES
EXIT_CONDITIONS
NEXT_UNITS
ASSET_REQUIREMENTS
```

质量要求：

- 同一节点被多个入口抵达时，至少有一句回应玩家来路的 callback。
- 选项不能引用玩家尚不知道的秘密。
- 失败必须产生新状态，而不是简单重试。
- 结局前必须有 closure 场景承接后果。

## 阶段 7：运行时

### Web 文字版

- Ink/inkjs 管理分支。
- TypeScript 管理 UI、存档和设置。
- `localStorage` 做轻量存档，`IndexedDB` 做完整状态和资源缓存。
- 场景背景、头像、环境音独立于叙事文本。

### Web 探索版

- Phaser 管地图、碰撞、交互物。
- Ink 管对话和剧情。
- 事件总线连接游戏对象与叙事状态。

### Godot

- Dialogic 管对话。
- Resource 或 JSON 管任务和世界状态。
- GDScript 管交互物、场景和存档。

### Unity

- Ink 或 Yarn Spinner 管叙事。
- ScriptableObject 管静态设定。
- JSON/数据库管动态存档。

### AI GM

- 事实库负责 canon。
- 检索器按场景读取少量事实。
- LLM 生成对话和描述。
- 规则引擎校验输出。
- 拒绝无依据新增关键事实。

## 阶段 8：资产生产

资产清单应先于美术生产：

```text
BG_001 格兰芬多公共休息室
BG_002 魔药课教室
CHAR_HARRY_NEUTRAL
CHAR_HARRY_WORRIED
UI_ICON_SAVE
SFX_OWL_WING
AMB_FIREPLACE_LOOP
```

每项记录：

- 来源和作者。
- 许可证。
- 可商用范围。
- 原始文件。
- 导出尺寸。
- 使用场景。
- 是否需要署名。

## 阶段 9：验证与质量门禁

### 自动检查

- JSON/YAML 可解析。
- 校验脚本在目标操作系统和默认终端编码下可运行。
- 节点 ID 唯一。
- 所有 `next` 引用存在。
- 所有变量和 flag 已声明。
- 从起点可达全部关键节点。
- 每条主路径至少到达一个结局。
- 不存在非结局死胡同。
- 所有结局可达。
- 所有成就可解锁。
- 自动随机走 10,000 条路径，统计覆盖和异常。
- 校验输出不依赖当前终端无法编码的 Emoji 或特殊符号。

### 人工检查

- 每个选择是否符合人物处境。
- 每个后果是否被世界承接。
- 是否存在换皮选项。
- 失败路线是否也有内容价值。
- 是否误用了后续书籍或原作外设定。
- 是否存在大段原文复述。

### 可用指标

- 路径覆盖率。
- 唯一节点访问率。
- 结局可达率。
- 选择分布偏差。
- 首次选择时间。
- 15 分钟完成率。
- 重开率。
- 文本重复率。
- NPC 事实冲突率。
- AI 每次生成延迟与成本。

## 阶段 10：发布与版本

- 剧情文件、状态 schema、资产清单分别打版本。
- 保存每个公开版本的剧本哈希。
- 存档包含 schema 版本和迁移函数。
- 用 feature flag 控制未完成章节和实验分支。
- 用户数据、AI 对话和遥测遵守隐私与未成年人保护要求。

## 最重要的验收标准

一个 15 分钟原型应满足：

- 玩家第一次做有代价的选择不超过 2 分钟。
- 至少一个选择会关闭另一条有价值路径。
- 三个结局都改变人物关系或世界状态，而不只是换一句结语。
- 玩家重玩时能看见之前没看到的因果，而不是跳过重复文本。
- 所有关键状态都能在最终结局中被回收。
